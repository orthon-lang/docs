## Decisions to record

1. **Ignore pattern for one position stays `_`** (not `?`). `?` is already taken by
   `?.`, `??`, Result propagation `?` and the reserved `?T` (NULL_SAFETY.md,
   TYPE_LEVEL_NULL_SAFETY.md). Syntax Principle 2 (SYNTAX.md): one symbol, one meaning.
2. **Rest pattern is `*x`** (collects the remaining elements into `x`); `*_` discards the
   remainder. `..rest`, `{name, ..}` and the `__` / `__rest` idea are withdrawn.
   `..` keeps its Range meaning (RANGE_SYNTAX.md) only.
3. **`*x` has the same form in both roles**: in receiving positions (parameters,
   patterns) it collects; in sending positions (call arguments, literals) it spreads.
   Rationale: mirror symmetry — construct and destruct look the same, exactly like
   `(x, y)` (EDR-055 principle 1, Representation Symmetry). Example:
   `first, *tail = nums` and `nums2 = (first, *tail)`.
   Consequence: amend the POLA section of `how/DESIGN_PRINCIPLES.md` (it currently says
   `*` always packs and never unpacks, contradicting EDR-055 principle 1): direction may
   be determined by position when the construct and destruct forms are mirror images;
   keep the "meaning must not depend on surrounding tokens" rule otherwise.
   Do NOT change the Semantic Purity table. Record the `*` vs numeric multiplication
   tension as an open question (no arithmetic operators are formally specified yet).
4. **Spreading `*x` applies to tuples and finite collections** (List, Array). Lazy
   iterators/generators are never spread silently: collect explicitly first
   (`*gen.to_list()`). Set spreading is left open (no order).
5. **Patterns in `for`, `case` and declarations are written without parentheses**, as a
   comma list: `for k, *rest in rows:`, `case first, *rest =>`, `x, y = point`.
   Parentheses are needed only for nested patterns and for the empty tuple `()`.
   (Expression-side tuple literals keep parentheses: `point = (x, y)`.)
6. **Labels: only explicit labels, written `value as label`**:
   `connect("example.com", true as use_ssl)`, `t = (1, 2, 3 as x)`,
   pattern `n as name, a as age = person`. The position of an element stays an implicit
   label (1-based, EDR-082). No implicit/soft labels from bare identifiers (rejected:
   silent argument-swap trap `sub(b, a)` and breaks positional destructuring
   `x, y = (10, 20)`). Labels do not participate in types or equality. A label overrides
   position when binding call arguments. Duplicate labels and double aliases
   (`3 as x as y`) are errors. The direction of `as` (thing on the left, name on the
   right) matches the only existing use, generic bounds `<Iterator as T>` (EDR-086).
   This replaces `name: value` at call sites in EDR-065 (`:` stays reserved for type
   annotations — GENERICS_SYNTAX rule 4, RANGE_SYNTAX rule 3). `:=` was considered and
   rejected (Go/Python-walrus meaning "declare/assign a variable"; reverses data-flow
   direction in patterns, breaking mirror symmetry).
7. **Exactly one `*` per pattern**, at any position, only in positional patterns
   (`first, *middle, last` is valid; `*a, *b` is an error).
8. **1-tuple exists; its only spelling is the constructor `tuple(a)`**; `(a,)` is
   forbidden; `(a)` is always plain grouping. `tuple()` equals `()`; `(a, b)` is sugar
   for `tuple(a, b)` (same literal-equals-constructor pattern as `[1,2,3]` = `List(1,2,3)`,
   EDR-041, and `a..b` = `range(a,b)`, EDR-083). Pattern form: `tuple(x)`.
   Rationale: the rest of a 2-tuple is a 1-tuple, so forbidding it makes the type of the
   rest depend on arity and breaks generic/recursive code (Haskell had to add `Solo`).
9. **`{}` record patterns are removed from UNPACKING.** An anonymous record is a tuple
   whose elements all have labels. Nominal types (`type Person(name: String, age: Int)`)
   are destructured only with the constructor pattern `Person(n as name, a as age)`
   (mirrors construction `Person("Alice" as name, 30 as age)`; consistent with
   `User(name, role: Admin)` in PATTERN_MATCHING.md). Anonymous patterns apply only to
   tuples (nominal-by-default, EDR-044; avoids visibility leaks, structural matching on
   field names, and two spellings of one concept).
10. **Destructuring declares variables without a keyword** (declaration by assignment,
    EDR-074): `x, y = point`; `var x, y = point` makes ALL names in the pattern mutable.
    The `let` keyword in UNPACKING examples is withdrawn (its fate is the dormant
    SEED-003; do not touch the seed). A pattern mixing new and already-declared names is
    a compile error. Same rule in `for var k, v in rows` and `case var first, *rest =>`.
11. **Per-element mutability is NOT supported** (only whole-pattern `var`); the
    workaround is a separate `var z = x`. Can be added later without breaking code.
12. **No default values inside patterns.** A default belongs to the whole parameter per
    EDR-065 (`fun distance(Point(x, y) = Point(0, 0))`); absence of a value is `Option`,
    use `??`. Reason: for a statically known tuple/type the field always exists, and
    `case (x = 0, y)` is visually ambiguous with the literal pattern `(0, y)`.
13. **Outside `match`, only irrefutable patterns are allowed** (declarations, `for`,
    parameters). Refutable patterns (literals, `Some`/`Ok`/variants) are errors there and
    legal only in `match`. Applying a tuple pattern to an `Option<T>` value is a type
    error; use `match`, `??` or flow-sensitive narrowing (TYPE_LEVEL_NULL_SAFETY.md,
    EDR-028). No implicit Option lifting.

Illustrative combined example for the EDR/UNPACKING.md (Orthon syntax):

```orthon
point = (10, 20)
x, y = point                         # declares x, y (immutable)
var a, b = point                     # declares a, b (mutable)
first, *rest = xs                    # rest pattern
n as name, a2 as age = person        # by label (anonymous labeled tuple)
Person(n as name, a as age) = p      # nominal type: constructor pattern
for k, *others in rows: ...
match xs:
    case () => 0
    case tuple(one) => one           # exactly one element
    case first, *rest => first + sum(rest)
connect("example.com", true as use_ssl)
```

## DEFERRED / OPEN (record explicitly; do NOT decide)

(a) Whether the whole `*` mechanism — variadic functions `fun f(*args)`, spreading in
calls, kwargs-like labeled remainder `fun wrapper(host, *opts): connect(host, *opts)` —
is included in v0.1: decided later. Working hypothesis: tuple elements may carry labels
(metadata), the remainder keeps its labels, so one `*` replaces both Python `*args` and
`**kwargs` (DESIGN_PRINCIPLES.md DRY). Variadic functions are already an open question
in `how/concepts/research/essential/FUNCTIONS.md` and EDR-065 open question 3.
(b) Move vs borrow on destructuring: to be decided JOINTLY for all constructs, not in
UNPACKING. Record the tracked discrepancy: EDR-055 Compliance item 7 and PATTERN_MATCHING
("matching consumes the scrutinee by default; borrowing via `&`") conflict with
COPY_ON_WRITE value semantics ("assignment creates a logical copy"). Do not rewrite the
PATTERN_MATCHING ownership wording — only add a short pointer to the tracked discrepancy.
(c) let-else / irrefutable single-arm match (PATTERN_MATCHING open question 4).
(d) Set spreading. (e) Map / `{}` literal syntax (COLLECTION_LITERAL_SYNTAX is candidate
only). (f) `*` vs numeric multiplication.

## Alternatives considered (use in the EDR "Alternatives Considered" table)

`?` as ignore; `..rest` kept; `__`/`__name` double-underscore rest; postfix `x*` for
spreading with prefix `*x` for packing (breaks mirror symmetry, POLA-style role reversal
on the same position); `f((nums))` double parentheses for spreading; `unpack(x)` as a
function at call sites (pseudo-function that yields several values); `x: 3` and `x:=3`
and implicit `x` ≡ `x as x` labels; `KV`/`Named<V>` carrier elements instead of tuple
labels; `{name, age}` anonymous patterns over nominal types; forbidding 1-tuples; `(a,)`;
per-element `var`; defaults inside patterns; let-else and implicit Option lifting;
keeping `let` for destructuring.
