## Iteration matrix — COPY VERBATIM into EDR-094 and ITERATION_LOOP.md

| Mode (loop side) | Borrow | Composition | Element values | `x` type | Needs `mut coll` | Collection after |
|---|---|---|---|---|---|---|

## Decision summary the EDR must carry (from the authoritative source)

- OQ2 resolved YES: `for` becomes an expression. Value position: `break v` /
  `return v` -> `Some(v)`; running off the end -> `None`; loop type `Optional<T>`;
  `break` with no value in expression position -> `None` early. Statement-position
  `for` yields no value. Simple predicate stays the `coll.find(|x| ...)` combinator
  (`Option<T>`); the `for`-expression is for multi-statement bodies with early exit.
  Scope is Optional search ONLY — fold/reduce stay combinators.
- OQ3 resolved NO: `for`-`else` rejected (foreign syntax; overloads `else`, breaking
  one-symbol-one-meaning; the search-and-not-found pattern is covered by Optional +
  `match`, so nothing is lost). Keep as anti-memory.
- OQ4 resolved: borrow-by-default. Three modes via ownership markers ON THE SOURCE,
  inherited from the language-wide vocabulary (NOT loop-specific `@iter_mut()` /
  `@borrow()` / `@grant()` methods): `for x in coll` (shared read `&T`),
  `for x in &mut coll` (exclusive write-borrow `&mut T`, requires `mut coll`),
  `for x in $coll` (move/consume `T`, rebind after). Diverges intentionally from
  Rust (bare `for` moves there). Structural (composition) mutation is NOT a
  `for`-mode (iterator invalidation) — it happens outside the loop. Interior
  mutability NOT introduced in v0.1 (recommendation to MUTABILITY OQ1).
- Authority frame to include: binding = authority held; grant = permanent transfer
  (`$`/move/reassign); rent = temporary loan (reference/borrow) split into read-rent
  (`&T`, many concurrent) XOR write-rent (`&mut T`, one) by the aliasing invariant.
  Plus the five additions: (1) aliasing invariant (many read-rents XOR one
  write-rent); (2) derivation rule (write-rent requires a `mut` binding — cannot lend
  more than held); (3) lifetime/return (a rent ends at loop scope automatically;
  a grant never returns); (4) grant consumes the holder (`$coll` needs no `mut` but
  leaves the binding dead -> rebind); (5) level (grant/rent in a loop operate on
  ELEMENTS; the structural axis is separate, outside `for`).
- Boundary flags B1-B4 (record as deferrals, NOT decisions of this EDR):
  - B1: ITERATION_LOOP inherits ownership/mutability markers; it does not define
    them. The `&`/`&mut`/`$` spelling is owned by Reference (GLOSSARY §Reference —
    "two forms: shared read-only reference and exclusive mutable reference") plus
    OWNERSHIP and MUTABILITY.
  - B2: `$` vs `move` glyph is open in OWNERSHIP_TRANSFER_OPERATOR; the loop inherits
    the final glyph.
  - B3: `&mut` spelling depends on MUTABILITY OQ3 (`mut` vs `&mut`); the loop inherits it.
  - B4: `&coll` cannot mean write-borrow — `&` already denotes the shared read-only
    reference; the `$`(one) / `&`+`&mut`(two) asymmetry is inherent (move is one
    operation; borrow is read XOR write forced by the aliasing invariant, so the more
    powerful write form is the more marked).

## Rejected forms — carry as anti-memory in Alternatives Considered
- Bare comprehension `expr for x in src where cond` — conflicts EDR-092 (bare
  parenthesised comprehension withdrawn; no production marker); `where` duplicates
  `gen(... if cond)`'s `if`.
- `opt(...)` / `find(...)` comprehension marker — duplicates `.find`; dresses
  aggregation as a production marker. Division of labour is fixed: production ->
  syntax (`gen`), aggregation -> combinator. Finding the first match is not
  boilerplate, so it does not earn syntax.
- `until` clause — extra loop keyword overlapping `while`'s negation.
- `for`-`else` — foreign syntax; overloads `else`.
- Loop-specific `@iter_mut()` / `@borrow()` / `@grant()` methods — rejected in favour
  of source-side ownership markers inherited from the language vocabulary.
