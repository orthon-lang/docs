run-off-end -> `None`; bare `break` -> `None` early); in statement position it yields no value;
scope is Optional search only — simple predicate stays `coll.find(...)`, accumulation stays
`fold`/`reduce` (EDR-094). (6) `for`-`else` is not part of the language — rejected by EDR-094;
the pattern is covered by the Optional for-expression plus `match`. (7) Iteration is
borrow-by-default; the markers ride on the SOURCE and are inherited from Reference / OWNERSHIP /
MUTABILITY — this record does NOT define them (cite EDR-094 boundary flags B1-B4); structural
mutation is not a `for`-mode. (8) The `$` glyph and the `&mut` spelling are provisional pending

Open with one framing sentence tying iteration to the same semantics/strategy split, citing the

Subsection "### Language Guarantees" — a bulleted list of the fixed, observable guarantees drawn
from ITERATION_LOOP.md, ITERATOR_PROTOCOL.md, and LAZY_SEQUENCE_GENERATORS.md: `for` desugars to
`IntoIterator::iter()` + `Iterator::next()` (single protocol, EDR-022) — reference the concept
doc for the desugaring rather than reproducing the full block; iteration is LAZY and SINGLE-PASS
(elements produced on demand via `next()`, an iterator is consumed as traversed, re-iteration
needs a fresh iterator from the source); NO hidden allocation — `for` and combinator chains
stream values without materialising intermediate buffers, materialisation is explicit via
`.collect()`; borrow-by-default — bare `for x in coll` is a shared read borrow (`&T`), with
explicit write (`&mut coll` -> `&mut T`) and move (`$coll` -> `T`) modes (EDR-094); generators
are stackless state machines implementing `Iterator<T>` (`emit` suspends/resumes, fixed-size
state, no per-instance heap allocation) — a language-observable guarantee (EDR-021).

Subsection "### Implementation Latitude" — a table matching the doc's existing "Semantics vs.
Execution" three-column shape (Aspect | Language (Semantics) | Implementation (Execution)) with
rows such as: dispatch (lazy protocol contract | eager vs. lazy realisation where semantics are
preserved); combinator overhead (zero-cost contract | monomorphisation to erase per-element
indirection); allocation (no hidden intermediate buffers | stack / arena / reuse). Add a
sentence that these are Strategy-Profile choices, not language semantics.

Subsection "### Iteration and Execution Contexts" — connect to EDR-085 WITHOUT duplicating the
Execution Contexts table: reference "the Execution Contexts table above (§ Invocation Semantics)"
(an in-document anchor link is fine). State the guarantee that `spawn()` / `fork()` worker
submissions return `void` and JOIN the generator stream — their results are drained through the
same lazy `Iterator<T>` protocol as any sequence, via `next()` / `stop()` or the `grab` / `gather`
StdLib sugar over the generator protocol — so distributed worker results are observed through
iteration, with no separate collection mechanism. Note that scheduling/threading is an
Implementation Strategy concern (Phase 7).
