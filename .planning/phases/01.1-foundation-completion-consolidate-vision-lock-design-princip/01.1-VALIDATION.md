# Phase 1.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | None — documentation-only repository, no build/test tooling |
| **Config file** | none |
| **Quick run command** | `grep -rn "11-step\|11 step\|11-stage\|11 stage" docs/` (should return zero matches outside `decision_records/` and `docs/notes/pipeline-throughput-gaps.md` after D-01 completes) |
| **Full suite command** | Manual read-through of every file listed in RESEARCH.md's Editing Map "target" and "cross-reference" columns, confirming each edit landed and no new dangling cross-reference was introduced |
| **Estimated runtime** | ~5 minutes (grep) / ~20 minutes (full manual read-through) |

---

## Sampling Rate

- **After every task commit:** Run the relevant single grep/read check from the Per-Task Verification Map below for the file(s) that task touched.
- **After every plan wave:** Re-run the full "Quick run command" grep for stale "11-step" text across the whole `docs/` tree.
- **Before `/gsd-verify-work`:** Manually re-read every file in RESEARCH.md's Editing Map target/cross-reference lists once more, since this is prose editing where grep can miss meaning-level errors (e.g., a status flipped to "Accepted" but surrounding content still reads as tentative).
- **Max feedback latency:** ~30 seconds (grep-based checks)
