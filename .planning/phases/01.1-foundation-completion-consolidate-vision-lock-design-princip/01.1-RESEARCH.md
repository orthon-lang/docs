## Common Pitfalls

### Pitfall 1: Fixing the wrong file for the "11-step" count

**What goes wrong:** `docs/how/concept-design-review.md` itself already correctly says "12-step" — a planner skimming CONTEXT.md's phrase "collapsed in place... from its actual current 12 steps" might assume the count inside the document also needs a pre-collapse "11→12" text fix, wasting a step, when the real fix in that file *is* the collapse itself (replacing the 12-step content with 3-5 steps), not a number correction.
**Why it happens:** CONTEXT.md's phrasing is easy to misread as "the 11-step count is wrong everywhere including the main document."
**How to avoid:** Treat `concept-design-review.md` purely as a collapse target (12 steps → 3-5 steps); treat the 5 cross-reference files (ROADMAP.md, REQUIREMENTS.md, CONCEPT_PIPELINE.md, PROCESS_INVENTORY.md, what/concepts/README.md) purely as "11 → correct new count" text fixes.
**Warning signs:** A task that tries to "fix the 11-step reference in concept-design-review.md" — that reference doesn't exist there; grep before editing.

### Pitfall 2: Editing TODO.md before the tasks it references land

**What goes wrong:** If D-04 (TODO.md edit) executes as the *first* task in the phase, GAP-02/03/04 will be cross-referenced as "not yet satisfied, deferred to PROC-02/05/FITNESS-01" — technically correct at that moment, but stale within the same phase once D-01/D-03/D-10 complete minutes later, recreating exactly the "stale checkbox" problem D-04 exists to fix.
**Why it happens:** TODO.md is alphabetically/thematically close to the start of a task list and might get scheduled early out of habit.
**How to avoid:** Sequence D-04 last (see Sequencing section).
**Warning signs:** TODO.md shows `Req: PROC-02` on a line for a feature that's already been collapsed by an earlier task in the same phase — should have been checked off instead.

### Pitfall 3: Editing EDR files to "fix" the 11-step count

**What goes wrong:** `EDR-007-concept-design-review.md`, `EDR-002-gate-system.md`, and `EDR-004-language-design-checklist.md` all contain "11-step" text. These are historical decision records — editing them would misrepresent what was actually decided at the time.
**Why it happens:** A naive repo-wide find-and-replace for "11-step" → "12-step" (or the final collapsed count) would sweep these files in.
**How to avoid:** Scope every "11-step" fix strictly to the 5 (or 6, including the discretionary `how/concepts/README.md`) files named in the Editing Map above — never touch files under `decision_records/`.
**Warning signs:** A diff touching any file under `how/decision_records/` for this phase should be treated as a red flag requiring justification.

### Pitfall 4: Losing the "5 steps, not 6-7 tokens" nuance in the collapse

**What goes wrong:** The Minimal Pipeline text names 7 tokens (Idea, Problem Description, Minimal Solution, Principle Check, Examples, EDR, CORE_CONCEPTS.md) but is called "five steps" in the same source document — a literal implementation could produce a 7-step or 6-step numbered list, technically outside the "3-5 step" requirement in PROC-02's own wording.
**Why it happens:** The source note itself is internally inconsistent between its prose count and its arrow-chain.
**How to avoid:** Follow this research's recommended reconciliation — 5 numbered procedure steps, with EDR + CORE_CONCEPTS.md registration split across the numbered-steps/Output-section boundary the document already has — or explicitly deviate with a documented rationale if the planner disagrees.
**Warning signs:** A new step table in `concept-design-review.md` with more than 5 numbered rows.
