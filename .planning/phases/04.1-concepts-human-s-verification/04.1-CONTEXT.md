<decisions>
## Implementation Decisions

### D-01: Verification fail behavior — non-blocking

Verification is **non-blocking**. A failing concept does NOT halt the current
wave. The agent records the failure and continues with the remaining concepts
in the batch and subsequent waves. The final governance plan (plan 18) is the
single place that processes all accumulated FAIL entries.

**Rationale:** Blocking per-batch would turn Phase 4.1 into an endless
fix-cycle if many concepts have minor issues. Phase 5 (Syntax Design) can only
start after governance completes — not after each individual fix.

### D-02: VERIFICATION-LOG.md — severity + required action format

Each entry in VERIFICATION-LOG.md follows this structure:

| Concept | Check-point | Severity | Required Action |
|---------|-------------|----------|-----------------|
| GENERICS | EDR Alternatives not stubs | WARN | Expand alternatives in EDR-NNN before Phase 5 |
| CONCURRENCY | Concept file missing (G1) | FAIL | Create what/concepts/CONCURRENCY.md from EDR-049 |

- **WARN** — issue exists but does not prevent Phase 5; governance plan addresses it.
- **FAIL** — must be resolved before Phase 5 can begin; blocks governance sign-off.

### D-03: FAIL threshold — only two conditions

Only two check-points always produce FAIL (hard blocker):
1. **Missing EDR** — concept was accepted without an EDR; this violates the project constitution.
2. **Missing concept file when EDR exists** — covers G1 (CONCURRENCY, PUSH_STREAMS,
   OBJECT_INITIALIZATION) and G3 (REQUIRE_USING_DEPENDENCY_SLOTS).

Everything else (stub Alternatives, stale cross-references, minor DESIGN_PRINCIPLES
tension) is WARN — still captured, still actionable, but non-blocking.

### D-04: Policy-level concepts in VB batches

ALLOCATION, REGION_BASED_MEMORY_MANAGEMENT, EXECUTION_PROGRAM, CONTEXT_PARAMETERS,
and REPRESENTATION_MODIFIERS were classified as Policy-level or handled as
corrections to existing documents (not standalone concept files). Verification for
these checks the **EDR + strategy file** (`how/strategies/`) rather than a
`what/concepts/` file. No FAIL for missing `what/concepts/` file when the EDR
records Policy classification or correction status.

### D-05: PB-батчи (unprocessed research) → Phase 4.2

The ~12 unprocessed research files (G4: EXECUTION_CONTEXT_INVOCATION,
EXECUTION_POLICY_HYPOTHESIS, MAKE_ILLEGAL_STATES_UNREPRESENTABLE, NAMESPACES,
COLORING_FREE_CONCURRENCY, DETACHED_EXECUTION, LLM_AS_DELEGATE_IMPL,
PARALLELISM_EXECUTOR_MODEL, STRUCT_AS_NOMINAL_PRODUCT_TYPE, plus OPEN_CLASSES,
SINGLETON_CLASS, MIXIN from deferrable) require **full Decision Pipeline treatment**.
That belongs in Phase 4.2, not here.

In Phase 4.1 (plan 17): the governance pre-step inventories these files with
verdict "Unprocessed → Phase 4.2", so Phase 4.2 CONTEXT has a ready scope.

### D-06: G6 consolidation — first step (plan 00)

VB batch runs**:

  from the EDR log** (EDR numbers are known from the existing plan files; the
