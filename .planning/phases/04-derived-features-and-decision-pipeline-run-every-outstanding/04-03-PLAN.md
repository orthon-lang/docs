    For each concept, follow the full procedure. Key concept-specific guidance:

    **CONCURRENCY_MODEL (high-risk):**
    - Classification per D-03: Language — concurrency model is a core semantic dimension (how concurrent execution is defined) with compiler-level guarantees (data-race freedom, isolation).
    - Design decision: Delegate-based model. Functions tagged with `act` or wrapped in `delegate` execute in isolation. Messages/mailbox for communication. No shared-state threads by default.
    - Cross-reference with CONCURRENCY (Plan 04-06, important tier): CONCURRENCY_MODEL defines the *model*; CONCURRENCY (important tier) defines concrete patterns. Recommend combined or explicitly linked EDRs to show how they relate.
    - Cross-reference with DELEGATE.md research: The delegate concept (from Phase 3's excluded-from-primitives list) is the execution policy mechanism for concurrency.
    - Gate validation: ARCHITECTURAL_INTEGRITY_GATE is critical — concurrency affects the entire execution model. IMPLEMENTATION_INDEPENDENCE_GATE too — the model must not depend on specific thread/async runtime.
    - Handle CONCURRENCY_MODEL + CONCURRENCY relationship per Claude's discretion (combined EDR or separate linked EDRs). If separate, the CONCURRENCY_MODEL EDR should explicitly note that CONCURRENCY (Plan 04-06) will build on it.

    **COMPOSABLE_COLLECTION_OPS:**
    - Classification per D-03: StdLib — `.map()`, `.filter()`, `.reduce()` are compositions of ITERATOR_PROTOCOL operations expressible as library functions. No new semantics beyond what the iterator protocol provides.
    - However, compiler-level optimization (loop fusion) may be an Implementation Strategy concern — note this in the EDR.
    - Dependency: ITERATOR_PROTOCOL (Plan 04-01) settled.

    **COMPILER_AS_STATIC_ANALYZER:**
    - Classification per D-03: Language — the compiler-as-static-analyzer concept is about the compiler providing a static analysis API that code can use (e.g., `@analyze` for linting, type checking, control flow analysis at compile time). This is a compiler-level API, not a runtime feature.
    - Design decision: This is a meta-concept — the compiler exposes analysis capabilities at compile time (via comptime or a built-in analysis API). It's language because the compiler IS the analyzer; there's no separate tool.
    - May affect HOW other concepts are designed (e.g., the analyzer can verify trait bound satisfaction, pattern exhaustiveness, ownership rules). The concept doc should describe what analyses are guaranteed vs. available as extensions.
