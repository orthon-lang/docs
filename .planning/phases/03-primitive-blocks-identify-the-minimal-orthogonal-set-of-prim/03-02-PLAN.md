  <files>what/PRIMITIVE_BLOCKS.md</files>
  <action>
    Conduct a systematic verification that every concept research document decomposes onto the primitive set defined in Plan 01. The verification must cover:

    **Step 1: Essential tier (22 files in `how/concepts/research/essential/`):**
    These are the Phase 4 concepts. For each file, verify that the concept it describes can be expressed as a composition of the 9 primitives. If the concept IS a primitive (e.g., FOUNDATIONAL_ABSTRACTIONS.md describes Data/Data Modifiers which is the organizing taxonomy), note that it validates rather than decomposes. For composite concepts, provide a brief decomposition path (e.g., "Error handling decomposes to: function (for try/catch blocks), call (for propagation), assignment (for result binding), scope (for catch boundaries)").

    **Step 2: Important tier (36 files in `how/concepts/research/important/`):**
    Use batch verification by category pattern. Group files by concept family (control flow, data structures, type system, metaprogramming, concurrency, etc.) and verify each group's core pattern decomposes. Note any edge case that might require a missing primitive.

    **Step 3: Deferrable tier (54 files in `how/concepts/research/deferrable/`):**
    For deferrable concepts (v0.2/v0.3), verify in batches by category. Since these are not expected to be implemented in v0.1, a lighter verification is acceptable — verify they are conceptually decomposable without reading each in full. Note any deferrable concept that would require a primitive not in the set.

    **Step 4: Reject tier (up to 4 files in `how/concepts/research/reject/`):**
    Verify that rejected concepts also decompose onto the primitive set (even rejected concepts must use the same primitive set — rejection is about principle violation, not composability).

    **Step 5: Essential-tier mapping completeness check:**
    The 10 source files for PRIM-01 synthesis must each have a recorded disposition in the EDR (Task 2). This task's verification output feeds the EDR.

    **Documentation approach:**
    Add a `## Verification` section to `what/PRIMITIVE_BLOCKS.md` with:
    - A summary table with tier, file count, pass/fail, and notes columns
    - Any gaps found and how they were resolved (or flagged if unresolvable — in which case the primitive set must be adjusted)
    - A statement confirming the set is minimal: "Removing any primitive would make at least one feature inexpressible"
    - List of specific concepts that validate each primitive's necessity (to prove minimality)

    For the verification, use file listing and grep/cat operations to efficiently sample the concept research files rather than reading all 132 in full. Focus deep reading on essential tier, use name-based pattern analysis for the rest.

    If any gap is found (a concept that cannot decompose), DO NOT silently adjust the primitive set. Document the gap, propose a resolution, and flag it in the summary. This is a quality gate — resolving gaps is part of the verification.

    Create EDR-NNN (next sequential number — check `how/decision_records/INDEX.md` for the current highest EDR number, the next in sequence becomes EDR-NNN) accepting the Primitive Blocks set.

    **Status:** Accepted
    **Date:** 2026-07-27
    **Category:** Architecture  
    **Scope:** Platform

    **Context section must include:**
    - Phase 2 established the Semantic Model (EDR-013) — 6 semantic dimensions. Phase 3 identifies the atomic operations (primitives) that serve those dimensions.
    - The 10 essential-tier source documents for PRIM-01 synthesis with their disposition:
      1. FOUNDATIONAL_ABSTRACTIONS.md — **Modified**: Data/Data Modifiers hypothesis adopted as organizing taxonomy (D-02), not as the primitive set itself
      2. EXCLUSIVE_DECLARATIONS.md — **Modified**: fun/proc/new adopted as tags on the function primitive (D-04), not separate primitives
      3. STRUCT_AS_VALUE_TYPE.md — **Superseded**: struct is not a primitive — built from pack + identifier + scope (D-03)
      4. CLASS_WITH_ACT.md — **Superseded**: class is not a primitive — built from pack + reference + scope (D-03); act decomposes to function tag + reference + scope
      5. ACT_AS_FUNCTION.md — **Superseded**: historical; superseded by DELEGATE.md before this synthesis
      6. FUNCTIONS.md — **Modified**: first-class function model adopted; function + call as separate primitives (D-04); explicit closure capture confirmed
      7. FINAL_BY_DEFAULT.md — **Not directly applicable**: governs inheritance policy, not primitive-level; orthogonal to primitive set
      8. NAMESPACES.md — **Superseded**: namespace is not a primitive — built from identifier + scope + visibility (D-05)
      9. DELEGATE.md — **Superseded**: delegate is not a primitive — built from reference + function + ownership (D-05); execution is orthogonal to declaration
      10. COMPOSITION_OVER_INHERITANCE.md — **Not directly applicable**: design pattern principle, not primitive-level; composition confirmed as primary mechanism

    - The 9 primitives with their categorization (3 Data, 6 Data Modifier) and definition reference to PRIMITIVE_BLOCKS.md
    - Key exclusions with rationale: operator definition, struct, class, delegate, namespace, act (as primitive)
    - D-10 resolutions: interior mutability = derived, closures immutable capture default, one `mut` keyword

    **Decision section:**
    Adopt the 9-primitive set as Orthon's Level 1 (Primitive Operations) in the Semantic Dependency Architecture, specified in `what/PRIMITIVE_BLOCKS.md`. This replaces the earlier 11-item hypothesis by removing operator definition, folding pack/unpack into one symmetric pair, decomposing struct/class/delegate/namespace as compositions, and treating fun/proc/new as function tags.

    **Consequences:**
    Positive: verified complete and minimal; Phase 4 can decompose any feature onto these 9; no missing primitive found across ~132 concept docs; excluded concepts have clear decomposition paths.
    Negative: none identified.

    **Compliance:**
    - Every Phase 4 concept must have a decomposition path onto these 9 primitives per PRIM-02 verification
    - If a Phase 4 concept cannot decompose, the primitive set must be revisited before Phase 4 completes
    - The verification section in PRIMITIVE_BLOCKS.md serves as the compliance record

    **Alternatives Considered:**
    - Two-primitive Data/Data Modifiers model (from FOUNDATIONAL_ABSTRACTIONS.md) — rejected as too coarse for Phase 4 decomposition verification per D-02
    - 11-item hypothesis (original set including operator definition) — operator definition rejected as syntactic sugar per Named Before Symbolic
    - Including struct/class as primitives — rejected per D-03 (type constructors are compositions of simpler primitives)
    - Including delegate as primitive — rejected per D-05 (execution policy, not atomic)
    - Including namespace as primitive — rejected per D-05 (organizational convenience)
    - Not separating function and call — rejected per D-04 (serving different semantic dimensions)

    **Related Concepts:** what/PRIMITIVE_BLOCKS.md, what/SEMANTIC_MODEL.md

    **Supersedes:** None — this is a new decision, not a replacement.
