# The Zen of Orthon

> **Reviewed against Working Backwards:** 2026-07-26 — verdict: consistent, no drift found. Cross-checked against `docs/why/WORKING_BACKWARDS.md` Derived Requirements table (R1-R6).

> Every special case creates complexity.

> Orthogonality removes exceptions.

> Rules are few and consistent.

> Just enough. Nothing less, nothing more.

> Consistency governs complexity.

> Simplicity is the result of orthogonality.

> What must be added is what failed to emerge.

> Explicitness reduces surprise.

> Abstraction hides complexity from view.

> What you learn transfers without exception.

> Code read by an LLM is code read by a human who has read every line you've ever written.

> LLMs mirror the signal in your code — ambiguity is amplified, not forgiven.

> A language predictable to an LLM is predictable to every programmer.

> Concise syntax is cheap; unambiguous semantics is priceless.

> The best code for an LLM is the same as the best code for a human — clear, consistent, and correct.
