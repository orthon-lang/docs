## Candidate Concepts

The following concepts from the essential/important tiers of `.planning/seeds/SEED-001-concept-research-tier-triage.md` have a direct LLM-generability connection:

| Concept | LLM Generability Gate Criterion Served | Rationale |
|---------|----------------------------------------|-----------|
| `EXCLUSIVE_DECLARATIONS.md` (essential) | Predictable generation, No hallucination surface | `proc`/`fun`/`new` classification makes operation semantics explicit — an LLM cannot confuse a procedure with a function because the syntax forces declaration |
| `IDENTITY_BASED_SAFETY.md` (essential) | Schema-serializable, Self-correctable | Explicit identity operators (`&`, `$`) are schema-serializable by construction; Static Analyser can trivially detect missing identity markers |
| `ERROR_UNION.md` (essential) | Schema-serializable, Predictable generation | Zig-style `!T` provides concrete, explicit error propagation with no hidden control flow — high schema-serializability |
| `COMPILE_TIME_EXECUTION.md` (essential) | No hallucination surface, Strategy-aware default | Unified comptime collapses generics/reflection/metaprogramming into one mechanism, reducing special-case surface that LLMs tend to hallucinate |
| `EXPRESSION_ORIENTED_LANGUAGE.md` (essential) | Predictable generation | Expression uniformity reduces context-dependent parsing — an LLM can always expect a value-producing construct, not a statement with different rules |
| `FINAL_BY_DEFAULT.md` (essential) | No hallucination surface | Immutability-by-default reduces hidden-mutation hallucination surface; LLMs cannot generate code that silently mutates state |
| `REPRESENTATION_MODIFIERS.md` (important) | Strategy-aware default | `struct(T)` / `boxed(T)` / `shared(T)` modifiers are explicit representation hints that map directly to Strategy Policies — an LLM can generate valid code under any strategy by default |
| `CONTEXT_LIMITED_MODULES.md` (important) | Self-correctable | Capability-based access control is schema-enforceable; Static Analyser can detect capability violations without runtime |

## LLM Generability Gate Requirement

Every concept, at acceptance time, **must pass the LLM Generability Gate as an additional check alongside its other acceptance criteria**. The gate criteria are defined in [`docs/notes/llm-generability-gate.md`](./llm-generability-gate.md) (lines 69-75) and consist of five independent criteria:

| Criterion | Description |
|-----------|-------------|
| **Schema-serializable** | The concept is fully expressible in a machine-readable grammar/type schema without loss |
| **Predictable generation** | LLM generates the construct correctly in ≥90% of attempts — no known ambiguity or special cases |
| **No hallucination surface** | No ambiguous or confusable constructs — every form has exactly one meaning |
| **Strategy-aware default** | Code generated by default is valid under any Implementation Strategy without annotations |
| **Self-correctable** | Static Analyser can detect and report LLM-generation errors for this construct with full diagnostic coverage |

This requirement connects VISION-03's shortlist output to PROC-01's acceptance gate in [`concept-design-review.md`](../how/concept-design-review.md) — the acceptance gate must reference the LLM Generability Gate as a mandatory step.
